# T1.6 — the audit trail trigger

**Work item**: WI-001 · **Task**: T1.6 · **Date**: 2026-08-02
**Migrations**: `20260802125955_aiqms_audit_trail_trigger`, `20260802130049_aiqms_audit_trail_redaction`
**Transport**: Supabase management API (`execute_sql` / `apply_migration`) — not the pooler

## Design

One generic writer, `aiqms.write_audit_trail()`, on six tables. The table-specific facts — which
column is the primary key, which column carries the owning `quality_record`, and which columns are
secret-bearing — arrive through `TG_ARGV`, so the function holds **no branch per table**. That is
the discipline `work/WI-001/SELECTED-DIRECTION.md` § Consequences imposes on the State Model engine,
applied here for the same reason: the alternative is six enforcement points that drift.

All six triggers are `ENABLE ALWAYS`, on the evidence of T1.2 rather than on principle.

## Two amendments to `work/WI-001/THIN-SPECS.md`, found by implementing it

**1. `audit_trail.row_id` was specified `bigint`; `app_user.id` is a `uuid`.** Auditing user
administration is not optional — `URS-ESIG-010`/`011` disable a user, and that act must be trailed —
so the column becomes `text` and carries the primary key rendered as text. Widening, applied before
any data existed.

**2. An `audit_trail.actor_id` foreign key to `app_user(id)` was added.** `URS-EREC-013` requires
attribution to a person; without the key that was an assertion rather than a constraint.

## The defect this task found, and why it was worse than an ordinary leak

The first version wrote every non-null column verbatim. Executing it showed
`app_user.signature_secret_hash` sitting in `audit_trail.new_value` in full.

Three things compound it:

1. the application role must hold `SELECT` on `audit_trail` for the read path (`URS-FUNC-009`), so
   every user's signature credential hash would have been readable by the application;
2. `audit_trail` is append-only and immutable by design, so a hash written there **can never be
   removed** — rotation under `URS-ESIG-009` would merely add a second hash beside the first;
3. Direction A exists precisely so this system controls the signature credential
   (`work/WI-001/RESEARCH-SLICES.md` §3). This would have surrendered that control on the first
   write, permanently.

Fixed by a redaction list passed as a trigger argument rather than held in a configuration table —
`URS-FUNC-057` requires the invariants to be enforced in code and not configurable away, and a list
that lives in a row is a list somebody can empty. Changing it now requires a migration.

The **fact** of the change is still recorded: column name, operation, actor, reason, instant and
zone. Only the value is withheld, because `URS-ESIG-009` needs credential rotation to be visible.

## Not yet covered

These assertions were executed as ad-hoc SQL through the management API, not as a pgTAP suite —
the Supabase CLI is not installed, so `supabase test db` cannot run. **The tests are owed**, and
this file is a record of a manual run, not a substitute for them. `URS-QUAL-002`'s coverage figure
cannot be claimed from it.

The trail is not yet protected against modification: `audit_trail` currently accepts `UPDATE` and
`DELETE`. That is T1.7, and until it lands the append-only property is a description of intent
rather than a property of the database.
