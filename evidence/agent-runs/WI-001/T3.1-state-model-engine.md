## What the suite covers

Every declared transition; each of the four Roles opening a Deviation; a user with no Role; the
wildcard making all five non-terminal states cancellable; the terminal refusal; both guard branches;
each of the five triage elements missing in turn; both limbs of `URS-FUNC-025` containment
resolution; and the Segregation Invariant.

Two assertions are worth naming.

**Segregation is checked before the signature is demanded** — and there is a test that a breach by a
user who supplied *no* signature still reports `AIQMS_SEGREGATION` rather than
`AIQMS_SIGNATURE_REQUIRED`. The order of checks is a control, not an implementation detail: reporting
a missing signature would tell the user to try again with one.

**The engine names no concrete Record Type.** `SELECTED-DIRECTION.md` § Consequences calls this the
discipline that keeps Option A honest, and asks for it as an explicit constraint rather than an
aspiration. The test reads the engine module's source and asserts no Record Type name appears in it.
Crude — but the alternative to a crude check is no check, and `RA-INIT-007`/`008` rate the invariants
holding across seven State Models as the highest-probability failure in the register.

## Parity, and what is still only vocabulary

`Outcome` uses the same code strings `aiqms.execute_transition` returns in `op_result.code`, and a
test asserts them. That is parity of **vocabulary**, not of behaviour: nothing here has compared the
Python engine's decisions against the database's on the same inputs.

That comparison is T3.2, it needs a connection, and `PLAN-DOCTOR.md` finding 2 requires it across
**three** encodings — this declaration, `aiqms.state_transition`, and `aiqms.record_state_catalog`.
Until it runs, the two engines are asserted to agree and not shown to.
